# Astraea — Live Project Status

**Updated: 2026-10-29.** This document tracks only merged capability, current blockers, and the next accepted work. Historical experiments and negative results remain available in Git history, [research notes](research/README.md), issues, and merged pull requests. The [project plan](PROJECT_PLAN.md) defines milestone criteria; an open PR is **not** merged functionality.

> **Research emulator, not a playable PS5 emulator.** No commercial PS5 title has executed its first instruction or produced a guest-rendered frame in Astraea. Independently authored Breakout has been interpreted **non-natively**, not executed as native x86 guest code. Production retail `diagnose` is pre-entry.

## Independent Breakout — exact stop

- Immutable, independently authored PS5-marked ELF SHA-256: `05c414993d1cd9e7182bbf5647be1ffad72c6ed6b6f5399d01af27281fef48b8`; source: [sharpemu-demo](https://github.com/sharpemu/sharpemu-demo) at `49e6b3b25678f14ec57a70b907ee215fddb608d8`.
- Structural census: five needed library names, twenty dynamic symbols, one `R_X86_64_RELATIVE`, nineteen `R_X86_64_GLOB_DAT`; NIDs match author declarations 19/19. A source declaration is **not** a verified Sony provider.
- Merged [#450](https://github.com/astraea-emu/astraea/pull/450) and [#452](https://github.com/astraea-emu/astraea/pull/452): the actual RELATIVE at guest `0x6900` is applied/read back in checked virtual memory; all 19 import slots are preflighted as guest-writable but kept byte-identical and unbound.
- Original entry plus callee: **13 source-backed instructions executed through a bounded external mediated CPU research engine**, with ten entry/callee guest stack writes. Merged [#468](https://github.com/astraea-emu/astraea/pull/468) verified batch CPU/memory parity; [#469](https://github.com/astraea-emu/astraea/pull/469) independently stopped via a pre-instruction hook at `RIP=0x23c`, GOT `0x68c8`, symbol 13, bare NID `Vo5V8KAwCmk` under a larger finite budget. The imported CALL did not retire and no Sony provider is fabricated.
- Merged [#453](https://github.com/astraea-emu/astraea/pull/453) and [#454](https://github.com/astraea-emu/astraea/pull/454): **static only** decoding of the post-call fallthrough observes four instructions without a RAX read before the next control boundary at `0x254`. Those instructions have **not** executed; service effects remain unknown.
- Merged [#476](https://github.com/astraea-emu/astraea/pull/476)–[#479](https://github.com/astraea-emu/astraea/pull/479) add bounded research-worker output, two repeatable Linux mediated Breakout child runs, partial seccomp host denials and Landlock filesystem-mutation canary checks. The source-owned 13-step trace independently predicts the synthetic caller GPR/RSP observation at the first unresolved imported CALL, and a forged-report negative is rejected; **no import retires**. The worker can still forge output if compromised and remains **not** a fully isolated arbitrary guest execution environment. #410 and #461 stay open.
- The pinned public source-to-ELF audit now establishes a *first-import demand record*: exact observed NID `Vo5V8KAwCmk`, GOT `0x68c8`, GLOB_DAT symbol 13, and **author-declared** `libSceSystemService/sceSystemServiceHideSplashScreen`. This provenance does not establish a Sony-provided export, service return, side effects, import dispatch or guest resume. Tampered first-GOT/symbol metadata is refused. See [#481](https://github.com/astraea-emu/astraea/pull/481).
- The host-compiled Breakout canvas reference from [#413](https://github.com/astraea-emu/astraea/pull/413) is **not** a frame generated by guest execution.

## First commercial-title C0 selection — provisional

**Dreaming Sarah** (`PPSA02929`, explicitly native PS5 on Sony Canada's store) is the provisional first-title candidate; Dead Cells and Animal Well are reserves. External emulator compatibility reports support feasibility but **do not establish Astraea's dependency closure cost**. As of this update, Astraea has **no local, lawfully accessed commercial PS5 ELF or genuine measured first-title C0 baseline**. The [local-only diagnostic procedure](research/c0_first_ps5_title_local_baseline_2026-10-14.md) uses existing `profile`/`dependencies` (and optional Linux pre-entry `diagnose`) to create a repeatable, aggregate-only report without running guest instructions or uploading copyrighted source bytes. Title priority can change after actual measured imports/mappings and runtime preconditions.

## Active blockers and work order

1. **Close controlled-source security increments without promoting untrusted code.** Merged [#455](https://github.com/astraea-emu/astraea/pull/455) confirmed writable non-guest VMAs in the actual tracee; [#456](https://github.com/astraea-emu/astraea/pull/456) admitted one source-owned decoded store while refusing the same store to a non-guest writable page; [#457](https://github.com/astraea-emu/astraea/pull/457) derives write authorization from exact guest ranges and prepared host-page permissions. Merged [#458](https://github.com/astraea-emu/astraea/pull/458) independently verifies that the same controller-owned memory plan matches the kernel VMAs before native source-owned fixture entry, with a deliberately wrong-permissions negative control. **No outside-authored native code is admitted.** See [#410](https://github.com/astraea-emu/astraea/issues/410). This remains a bounded test-only route, **not** a complete x86 memory mediator. The source-owned mediated PS5 ELF in #471 also has original RX/RW byte extents sharing a 4-KiB backing page; its one authorized store and full memory image were verified but a general byte-range write barrier was not established.
2. **Make an execution-backend decision with measured evidence.** Merged [#467](https://github.com/astraea-emu/astraea/pull/467) compared batch, code-hook and single-step execution on the same owned x86 workload: the batch approach was faster on its measured CI runner, not a PS5 game-performance proof. Merged [#464–#466](https://github.com/astraea-emu/astraea/pull/466) established limited effect/fault ledgers and an external-engine interchange, not a production backend.  Compare an enforceably isolated native lane with a mediated x86-64 interpreter/DBT lane on the same source-owned workload. Require explicit guest memory ownership, stack/implicit writes, control-flow/fault rules, complete effect accounting, performance and portable host behavior. Do not grow one-opcode ptrace guards into an unbounded pseudo-emulator.
3. **Advance one unchanged independent executable.** [Breakout #378](https://github.com/astraea-emu/astraea/issues/378) is the selected homebrew workload. Authenticate the first required imported-service ABI/effects rather than assigning a generic return value. Native Breakout remains prohibited by [#410](https://github.com/astraea-emu/astraea/issues/410); its true guest RWX permissions and host 4-KiB page collision at `0x6000` also remain unresolved.
4. **In parallel, allow C0-only lawful commercial diagnostics.** Read-only static analysis of authorized local content can inform first-title selection without enabling execution. Never commit retail binaries, firmware, keys or proprietary SDK contents.
5. **Reference hardware only for irreducible evidence.** [#334](https://github.com/astraea-emu/astraea/issues/334) requires two same-build, normal-title pre-CRT/procparam observations and a demonstrated firmware-specific launch/log route. No PS5 networking, updating, login or console experiment is currently requested.

## Milestone definitions

- **C1:** evidenced real PS5 process-entry ABI and first lawful retail instruction. **Not complete.** Independent homebrew non-native interpretation does not satisfy it.
- **C2.0/C2/C3:** typed post-entry divergence, runtime dependency closure, then sustained initialization/boot. **Not complete.**
- **C4/C5/C6:** guest-title headless frame, presentation/menu, then playable/reference-validated route. **Not complete.**
- **V0–V3:** bounded owned graphics gates complete; **V4–V5 remain future**.

## Engineering rules

- Ship focused, end-to-end outcomes with an owned fixture, a source-pinned real-workload observation when applicable, negative tests and a **seven-check exact-head CI merge gate** (five platform/fuzz/sanitizer jobs and two C1 pinned workflows).
- Separate **static analysis**, **source-owned synthetic/native research**, **independent homebrew**, and **commercial retail** evidence. Never promote a finding across these categories by implication.
- Treat unknown Sony ABI/service semantics as typed unsupported stops; preserve provenance, negative results and clean-room restrictions.
- Read [README](../README.md) for a newcomer overview, [PROJECT_PLAN](PROJECT_PLAN.md) for long-term definitions, [ADRs](adr/README.md) for accepted architecture, and [research notes](research/README.md) for dated evidence.
- Repository branch/admin hygiene is tracked in [#168](https://github.com/astraea-emu/astraea/issues/168); no historical branch deletion is justified solely by age or name.
