# Project Status

**Merged research frontier: through #436, with the checked guest fetch/step addition in this change.** C0 Linux read-only/pre-entry diagnostics and bounded V0–V3 graphics are merged. C1 remains active and **no commercial PS5 title has executed its first instruction, booted, produced a title-generated frame, reached a menu or become playable in Astraea**. This is an engineering-research emulator, not yet a playable PS5 emulator.

The [project plan](PROJECT_PLAN.md) defines durable C/V/S gates. This file is the **live merged frontier and next dependency**; open issues/PRs are proposals, not implemented functionality. [Research notes](research/README.md) and [ADRs](adr/README.md) preserve historical evidence.

## Merged evidence (not game compatibility)

- **Loader / diagnostics:** bounded PS5/SCE ELF parsing, mappings, dynamic symbol/relocation/TLS inventories, source-pinned public artifact profiles, checked diagnostic classifications; production `diagnose` still rejects the independently authored raw Breakout ELF before entry.
- **Controlled native execution:** Linux/Windows owned probes, typed syscall and fault stops; Linux has a separate sealed-artifact worker and finite resource limits. A separately source-built **minimal PS5-format ELF** executed its deliberate first `UD2` instruction twice, after eight checked `R_X86_64_RELATIVE` writes ([#403](https://github.com/astraea-emu/astraea/pull/403)). An exec-separated research leaf now performs actual GuestImage entry, normalized typed fault observation and a source-owned host-IP escape-denial test ([#419](https://github.com/astraea-emu/astraea/pull/419)–[#421](https://github.com/astraea-emu/astraea/pull/421)). This is not arbitrary hostile-code containment or external-title entry.
- **Owned linking:** independently linked generic ELF client/provider `JUMP_SLOT` transfer, synthetic PS5/SCE-profile `GLOB_DAT` gate, checked patch/readback and negative cases. No full Sony module graph or arbitrary import binding is established.
- **Independent Breakout corpus:** SHA-256 `05c414993d1cd9e7182bbf5647be1ffad72c6ed6b6f5399d01af27281fef48b8` identifies the pinned PS5-marked raw ELF. Static profile: **5** needed library names, **20** dynamic symbols, **1** `RELATIVE`, **19** `GLOB_DAT`; source-to-ELF NID comparison matches **19/19** ([#404](https://github.com/astraea-emu/astraea/pull/404), [#406](https://github.com/astraea-emu/astraea/pull/406), [#408](https://github.com/astraea-emu/astraea/pull/408), [#409](https://github.com/astraea-emu/astraea/pull/409)). Source-pinned real GuestImage staging tests established 20 writable, non-executable relocation destinations and one **RWX executable PT_LOAD**; a copied RX-only mapping plan is still rejected because executable PH0 and writable PH1 share 4 KiB host page `0x6000` ([#422](https://github.com/astraea-emu/astraea/pull/422)–[#423](https://github.com/astraea-emu/astraea/pull/423)). A disposable, non-guest-VA scratch page staged and read back only one `RELATIVE` patch at `0x6900` before RW→RX and a verified kernel write refusal ([#424](https://github.com/astraea-emu/astraea/pull/424)); **19 GLOB_DAT imports remain unresolved**; the pinned Breakout has not executed natively. These counts **do not** establish resolved providers or executed service calls.
- **Research-only non-native Breakout CPU interpretation (#425–#436):** source-backed decoding of the entry and callee now models **13 genuine homebrew instructions**, including **11** callee retirements and **nine** callee stack writes, stopping at `RIP=0x23c` before the unresolved indirect imported CALL (`GOT=0x68c8`, symbol 13, bare NID `Vo5V8KAwCmk`). The source ties this NID to `sceSystemServiceHideSplashScreen`, but no Sony provider, authentic ABI, import transfer or service result is established. `OwnedGuestAddressSpace` mediates virtual guest access for caller-owned memory, while `step_owned_x86_64` models only PUSH/MOV/SUB/store cases. This change adds fresh permission-checked virtual instruction fetching, one-instruction decoding, finite-budget stepping and typed pre-retirement stops with independent fixtures. This is not native-code containment, a full x86 interpreter or evidence of title gameplay.
- **Breakout CPU-only reference:** [#413](https://github.com/astraea-emu/astraea/pull/413) merged a source-hash-guarded **host-compiled**, 480×270 first-frame reference (FNV-1a64 `11521d6d6940fe57`). The frame was **not** produced by Astraea guest execution or PS5 VideoOut.
- **Graphics:** selected owned shader/PM4/DCB and Vulkan raster/readback paths; no general PS5 shader ISA, GPU memory coherency, synchronization, tiling/compression, VideoOut, or title-rendered frame.
- **Verification:** five standard Linux/Windows/macOS/sanitizer/fuzz CI jobs plus pinned evidence workflows; passing a test only proves its asserted and explicitly scoped behavior. Seven exact-head jobs passed for #436: five standard platform/sanitizer/fuzz checks plus the pinned C1 observer and independent Breakout workflows. The latest fetch/step addition requires its own exact-head CI before being treated as merged.

The larger pinned public native-title + non-Sony PRX studies remain preserved in [research](research/README.md): their `_init_env`, module-identity, relocation and runtime-contract uncertainty does not justify pretending a service is implemented.

## Active C1 dependency — ONE selected executable path

**Target:** the exact independently authored **Breakout ELF** with justified guest startup, service semantics and eventually a controlled native/test execution boundary. Its **non-native synthetic-context pre-CALL stop is already verified** at `0x23c` and does not fulfill native import transfer or a validated Sony process entry. **Native blocker:** true executable PH0 and writable PH1 share host page `0x6000`; the original source requests RWX and strict native W^X still rejects it. The checked virtual guest memory path does not change that native constraint. **Semantic blocker:** no authenticated runtime provider/ABI contract exists for the first imported service. This is **not C1 commercial-title completion**.

1. **Security prerequisite — [#410](https://github.com/astraea-emu/astraea/issues/410):** guest-IP-only seccomp is not hostile-code containment. The source-owned real GuestImage escape-denial regression passed in the independently exec-separated constrained research leaf (#419–#421), with no effectful controller IPC. However clone/memory capabilities, guest-to-host control transfer, descendant lifetime, and unauthenticated leaf observations remain explicitly incomplete. Production `diagnose` is pre-entry; do **not** admit independently authored code until the relevant boundary is actually demonstrated. Historical #414 and #415 proposals are **not merged security mitigations**.
2. **Breakout executable integration — [#378](https://github.com/astraea-emu/astraea/issues/378):** preserve exact ELF/source hashes; verify all required mapping and relocation writes with owned memory lifetime; distinguish the bare-NID source declarations from independently verified runtime provider/module identity; refuse ambiguity before any unsafe transfer. Reuse existing loader, patch and gate primitives, not new standalone prototypes. Extend the checked, source-backed non-native pre-CALL observation into defensible guest semantics; preserve its typed stop and exact RIP/NID with negative/tamper tests. Actual guest import transfer and service behavior require independently supported providers, and native entry requires separate containment and mapping evidence. No guessed Sony return values or general HLE catalog.
3. **First lawful retail title — in parallel, read-only:** select a simple offline, low-closure primary candidate (and backups) from public evidence; if a legitimately obtained, authorized executable is locally available, run **C0 static preflight only**. Do not commit retail bytes, keys, firmware or modules. This can happen before C1 native execution is ready.
4. **Reference PS5 — [#334](https://github.com/astraea-emu/astraea/issues/334):** collect two same-binary *normal home-screen native-title* pre-CRT/procparam observations **only when** a firmware-13.00-specific launch/logging route, frozen observer, precautions and a selected-path irreducible ABI question are confirmed. Payload-loader entry is not equivalent. Until then, **no console operation, network connection, firmware update or login is requested**.
5. **Commercial C1 then C2.0:** only after actual selected-path ABI evidence is sufficient ([#348](https://github.com/astraea-emu/astraea/issues/348)), reproduce the first lawful commercial instruction and then its first typed post-entry divergence ([#350](https://github.com/astraea-emu/astraea/issues/350)). Boot, frame, menu and playability are **later separate milestones**.

### Work selection rule

Every new PR should close a **measured first blocker** on the chosen executable path, establish required security/accuracy evidence, or prevent a documented regression. No second synthetic `GLOB_DAT` proof, broad HLE catalog, speculative graphics breadth, or new status document as a substitute for integrated progress. Use exact-head CI and explicit *what this does not prove* language.
