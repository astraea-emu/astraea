## #15 scope

- generate an Astraea-owned deterministic ELF64 fixture
- two standard `PT_LOAD` segments: RX code and read-only data
- validate the generated bytes through the strict M1 `GuestImage` pipeline
- prepare exact-address Linux guest memory
- enter native x86-64 guest code through the guarded backend
- call `astraea.test.write`
- require the resumed guest to observe the consumed-byte count in RAX
- capture exactly `Hello from guest`
- resume and call `astraea.test.exit(42)`
- stop without executing the post-exit `UD2`
- record structured guest-entry, gate-stop, HLE-resume, and HLE-exit events
- require repeated runs to produce identical structured results

The guest probe deliberately executes `UD2` if the write return value is wrong
or if `test.exit` incorrectly resumes, preventing a false-positive prototype.
